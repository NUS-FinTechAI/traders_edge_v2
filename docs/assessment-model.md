# Assessment model

The current implementation checks understanding of authored questions. It does not establish real-world investment suitability, trading competence or profitability. The [ten-module teaching contract](curriculum/README.md) specifies prerequisites, outcomes, named playable tasks, pre/post dimensions and sample items, required/optional criteria, remediation and source/v1 mappings for every module in the research brief's order.

**Status:** the canonical 30 lessons, 60 legacy practice questions and 50 module-check questions remain authored and pending independent financial-accuracy approval. The merged backend supplies diagnostic and interactive decision-task runs for all ten modules, but not the complete proposed scenario/mission experience. The broader assessment examples, parallel forms, unseen delayed banks and mission rubrics below are **design proposals**, not validated learning measures. The 80%-plus-critical rule is a current product rule; extending it to the target contract does not validate it.

## Implemented learning rules

Lessons unlock sequentially within a module. All required lessons must pass before its five-question check; earlier module checks gate later modules. A lesson requires every graded required task correct, including the simulation audit where bound; a delayed review requires every question correct. A module check requires at least four of five correct and every critical risk item correct. Critical errors cannot be averaged away by unrelated answers. These thresholds are product rules awaiting evaluation.

The server persists graded attempts, selected answers and feedback. The legacy submission contract requires recorded, unassessed reflection; a length check does not establish quality. All ten modules now use persisted diagnostic, practice, bonus, exit and delayed-review runs without mandatory essays. Review runs require an owned, due, uncompleted review; new canonical whole-review writes are blocked, while stored legacy replay and supported unversioned fixtures remain compatible. Review list/detail exposes latest and active run IDs; resume the pinned run, not current-catalog questions. Practice decisions receive immediate feedback and retries; diagnostic, exit and review answers freeze on submission, with correctness/explanations withheld until the form completes. An incorrect diagnostic never blocks learning or awards mastery. Confidence remains optional, 0–100, and does not change passing or rewards. First responses and later retries remain separate evidence; a first recorded diagnostic does not prove the learner has never seen the material, particularly after legacy progress. Rewards occur once per learning event.

A passed lesson schedules a check using its pinned `review_after_days` (currently one day). Review runs pin the familiar lesson questions, rubric, approval/content version and review interval. Failure completes the run and reschedules from failure time using that pinned interval, not the current catalog; start a new run when due again. Passing requires all items correct, completes the queue item and grants 10 XP once under `review:<lesson_id>`. That is retrieval practice with a familiar question bank, not an independent retention or transfer test. The separate delayed-review prompt in the catalog is teaching copy, not a second scored question bank. Module checks are distinct from practice questions but overlap in concepts and some familiar arithmetic patterns; passing after feedback may include memorization.

The API's `mastered` field means the current module-check rule was met. Product copy should say **module check passed** and show the rule; avoid interpreting this storage label as an independently validated mastery certification. Delayed review and unfamiliar application are additional evidence, and currently do not determine module unlocking. The older bonus reflection prompts remain `content_only`. Each level's separate bonus tasks now produce verified completion stars; these are completion states, not evidence that reflection text was assessed.

The generic simulation backend already supports guided sessions after the first four checks and endless sessions after the first nine. `server/app/simulation/api.py` requires a written plan on each actual order; the engine records plans and fills. It does not semantically grade the plan text. Module 9 still needs lesson-to-scenario/mission binding and an assessment rubric; do not describe its generic backend simulator as absent. Current mode gates do not prove retained mastery or enforce the proposed per-lesson progressive tool gates.

Only `m05-l01` now includes a final required simulation audit after knowledge cards. A pinned `interactive-2` run uses `simulation/bindings.py` and `lesson_api.py`; ordinary routes enforce its action policy. Accurate observed order/status/fill/limit/fee facts and rejection of the fill guarantee are required; with no orders, verify `no_thesis_supplied` or `current_ask_above_cap` using the current ask. The no-thesis case is educational, not a recommendation. Stale audits return 409 before evidence; incorrect audits retain issue-specific corrective feedback. Preserve the pre-finish audited snapshot separately from cancellation on finish. No profit, order count or fill reward is involved; free-text plan quality remains unassessed. Other bindings and Module 9 multi-scenario assessment remain pending. See the [canonical bound contract](../server/README.md#bound-m05-l01-simulation).

Implementation evidence: `server/app/content/catalog.json`, `server/app/learning.py`, `server/app/learning_runs.py`, `server/app/progression.py`, `server/app/simulation/lesson_api.py`, `server/app/simulation/api.py` and `server/app/simulation/engine.py`. Financial concept scope is recorded in the [source register](curriculum/sources.md); investor-education sources do not establish that these scoring thresholds or game mechanics are effective.

## Target assessment cycle — design proposal

| Stage                        | Learner action and evidence                                                                                                                                                        | Feedback and gate                                                                                                                                                                               |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Entry diagnostic / pre-quiz  | Submit all baseline items, allowing an explicit “not sure”; record first answers and optional confidence before instruction, worked examples or hints.                             | Withhold correctness and explanations until the complete diagnostic is submitted. Wrong answers do not block teaching or penalize rewards. Earlier module prerequisites remain in force.        |
| Teaching and guided practice | Read a short instruction and solved example, predict, then sort, calculate, inspect evidence, allocate or act in a bounded scenario. Capture the task result and relevant choices. | Give immediate specific feedback, explanations and unlimited retries. Fade scaffolding on fresh practice. Record hints and retries separately from first unaided attempts.                      |
| Required mission check       | Complete each module's named required tasks. Verify the actual allocation, constraint, evidence selection or decision record, not a “done” click.                                  | Correct task errors through targeted practice. Suitable no-trade choices count; an order or favorable return is never required merely to generate activity.                                     |
| Exit / post-quiz             | Complete a distinct application form after required tasks. Capture answers, confidence, form/version and whether any item was previously seen.                                     | No in-form correctness, hints or answer explanations. Release feedback only after the whole form. Proposed gate: at least 80% plus every critical item correct and all required tasks verified. |
| Remediation and retry        | Reopen the failed concept's worked example and action task; then complete a fresh exit form. Keep the original result.                                                             | Do not repeat the v1 one-attempt lock. A known solution can support practice but cannot become a fresh baseline or unseen transfer result.                                                      |
| Delayed review               | At the provisional 24-hour interval, retrieve the concept in a new context without the solved example; separately record elapsed time and prior exposure.                          | Release feedback after the review set, then reteach as needed. Current repeated items remain labeled familiar retrieval until reviewed unseen variants exist.                                   |
| Optional bonus               | Complete an additional, objectively verifiable task specified in the module contract.                                                                                              | Optional, retryable and non-blocking. A verified bonus event may receive a one-time marker; note length, stars, XP, order volume or profit never establish learning.                            |

Parallel forms and delayed unseen tasks are **pending authoring and independent review**, not a capability implied by the table. Distinct wording is insufficient: specify the same construct, comparable difficulty, scoring key/rubric and critical-risk coverage while changing the decision context. Do not call two forms equivalent until reviewed and evaluated. Neither the current five-item checks nor the illustrative samples below exhaust each module's dimensions.

The target must not require an essay for routine diagnostics, quizzes, sorting or calculations. Reflection can be demonstrated by selecting the mistaken assumption, identifying contradictory evidence or revising a decision with a structured reason. Keep optional learning notes, but do not automatically grade their semantics or reward length. **Every actual simulated order still requires a written pre-order plan**, including exits and replacement orders. This boundary is independent of the quiz-reflection change.

## Module assessment blueprint — design proposal

Samples below are new author-facing examples with intended answers, not a published question bank. The curriculum contract supplies the concrete level actions, worked examples, additional samples and source mappings. Pre-quiz dimensions identify starting beliefs; exit dimensions test application in a changed situation rather than recall of those same items.

| Module                       | Entry dimensions and sample                                                                                                                      | Distinct exit dimensions and sample                                                                                                                                                                              | Critical risks, remediation and delayed evidence                                                                                                                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Money Before Markets      | Purpose/horizon, capacity versus willingness, recovery beliefs. “Can comfort with loss make next month's essential bill money risk-capable?” No. | Constraint-based budget transfer, shortfall arithmetic, justified waiting. “A required 800 loses 5%; can hoped-for recovery cover the 40 due now?” No.                                                           | Essential-needs exposure and guarantees are critical. Re-sort the fictional budget; later classify a different deadline/irregular-income case.                                                                                   |
| 2. How Markets Work          | Roles, quote sides and displayed liquidity. “Is a broker the issuer of every share it displays?” No.                                             | Route interpretation, spread arithmetic, stale/insufficient depth. “Bid 7.90/ask 8.10: is spread 0.20 or the candle's high minus low?” 0.20.                                                                     | Quote quantity/time as guarantees is critical. Revisit buyer/seller and depth cards; later inspect an unseen thin quote.                                                                                                         |
| 3. Investment Products       | Ownership/debt, distributions and fund-label assumptions. “Does a bond's promise remove default risk?” No.                                       | Total-return components, bond resale risk, fund structure/cost/overlap. “Price 30 to 28 plus distribution 1: positive total change before costs?” No, −1.                                                        | Product/return guarantees and missing material risk are critical. Rebuild return/risk cards; later compare unfamiliar holdings and fees.                                                                                         |
| 4. Building a Portfolio      | Weights, ticker-count diversification and fair comparisons. “Are two funds necessarily unrelated exposures?” No.                                 | Goal-constrained allocation, look-through weights, drift/cost decision, benchmark fit. “120 direct plus 60 indirect out of 600: issuer weight?” 30%.                                                             | Essential cash and hidden concentration are critical. | 5. Safe Execution            | Price/fill certainty, stop guarantees and costs. “Does a limit guarantee a fill?” No.                                                            | Price-constraint ticket choice, stop/gap trace, partial-fill receipt and settlement distinction. “A triggered sell stop meets only lower bids: is the trigger a guaranteed fill price?” No.                      | Missing pre-order plan and guarantee claims are critical. Replay trigger versus fill; later reconcile a new gap/fee/partial-fill trace.                                                                                          |
| 6. Managing Risk             | Exposure, planned versus possible loss, drawdown/recovery. “Does a 25% fall need only 25% recovery?” No.                                         | Stress sizing, peak-to-trough and recovery arithmetic, probability/cost reasoning. “Eight at 30 gap to 24 plus 2 fees: within a 40 stress budget?” No, loss 50.                                                  | Stop-as-cap and knowingly exceeding the scenario's risk budget are critical. Use the exposure grid; later review a path with more than one peak and trough.                                                                      |
| 7. Making Decisions          | Source credibility, observation/inference and certainty beliefs. “Does a popular post verify its claim?” No.                                     | New evidence/falsifier selection, incentive checks, probability interpretation. “Does a forecast of 80% make one failure impossible?” No.                                                                        | Unverified guaranteed signals are critical. Rebuild a provenance chain; later test a different conflicting-source case. Confidence remains optional and cannot excuse a critical error.                                          |
| 8. Psychology and Protection | Outcome bias, social proof, urgency and authority trust. “Does a profitable result establish a sound process?” No.                               | Outcome-blind process judgment, conflict identification, independent scam verification. “Verify a suspicious official-looking message using its own supplied link?” No, find the official channel independently. | Unsafe credential/payment routing and guarantee acceptance are critical. Rehearse verification paths; later triage a different channel/impersonation.                                                                            |
| 9. Integrated Simulation     | Plan completeness, order/fill distinctions and hindsight. “Does submitting ten units establish a ten-unit holding?” No.                          | Held-out scenario planning, actual-fill reconciliation, pathwise adherence and correction. “A winning decision exceeded the written exposure constraint: compliant?” No.                                         | Missing plans, knowing constraint breaches and false fill history are critical. Replay the failed process step; later use an unseen path/seed, with reasoned no trade valid.                                                     |
| 10. Optional Advanced Paths  | Deposit/loss beliefs, short lifecycle and rights/obligations. “Is a futures deposit always the maximum possible loss?” No.                       | New adverse leverage calculation, short close-out, buyer/writer/futures distinctions. “A short rises from 10 to 16 for five units: before costs, loss?” 30, not capped by sale proceeds.                         | Deposit-as-cap, capped short-stock loss and buyer/writer equivalence are critical. Rebuild obligations/cash diagrams; later use a different product and adverse move. Completing core modules never requires this optional path. |

Each row needs multiple reviewed items across its dimensions, including plausible misconception-based distractors, balanced correct-option positions, accessible inputs and an explicit “not sure” policy. Critical flags must follow potential harm and the objective, not be added indiscriminately to force 100%. An overall score must not hide a missing dimension. Neither sample items nor this blueprint certify the current question bank as adequate.

## Decision and mission evidence — design proposal

Keep separate evidence streams instead of one “skill” or virtual-profit score:

- **Knowledge and risk recognition:** first-attempt responses by dimension, score denominator, critical-risk errors and form/content edition. Keep item-level errors even after a later pass.
- **Readiness and allocation:** selected goal constraints, destinations/weights and calculated look-through exposure. More than one allocation may satisfy a fictional brief; do not grade against an arbitrary personal-investment recommendation.
- **Evidence and protection:** selected provenance, date, incentive, disconfirming fact or verification route. Record why a no-trade choice fits the supplied constraint using structured reasons; do not reward inactivity alone.
- **Planning:** order-linked reason/evidence, size/exposure, planned loss versus stress possibility, order constraint and reconsideration/exit rule, recorded before the order. Validate required fields and numerical/structured consistency; nuanced free-text plan quality needs a reviewed rubric and, where necessary, human review. A minimum length is not that rubric.
- **Execution and adherence:** server-authoritative order/fill/cancellation history, actual friction and exposure through time, compared with the prior plan. A cancelled/unfilled submission is not a fill; a final snapshot cannot establish that a concentration limit held throughout. An adverse gap outside a planned estimate is not automatically a knowing breach: distinguish insufficient risk recognition, execution surprise and deliberate deviation.
- **Reflection/correction:** identify a concrete mismatch or uncertainty and a justified revised action. Verify a selected/corrected task or apply an approved human rubric; do not claim current stored reflection is semantically assessed.
- **Retention/transfer:** elapsed time, context novelty, form and scenario exposure, hints and first attempt on the unseen task. Retrying an already explained item measures supported correction, not independent transfer.

A task record must identify learner, objective/lesson, task/form version, attempt, timestamp, required/bonus role, response or action evidence, hint/feedback exposure and scoring/rubric version. Scenario evidence additionally needs approved provenance, generator/data version, seed, friction assumptions and a private future path. These are proposed extensions to the existing run evidence, not a new runtime format defined here. Keep future state and private answer keys out of all public lesson and session responses.

Normal completion markers may report verified required tasks and a passed check. Proposed bonus verification uses the additional deadline, quote, cost, overlap, non-fill, stress-budget, counterexample, impersonation, adverse-path or product-refusal task specified in each module. Award once for the verified task/version, not each retry. Stars and XP are engagement records; they do not replace knowledge, risk, adherence or retention evidence. Never reward profit, trade count/volume, a lengthy note or simply opening a tutorial panel.

## Unlocks and remediation — design proposal

Keep the source-ordered ten modules. Entry diagnostic completion captures a baseline but its score never blocks teaching. Required tasks plus the proposed exit rule unlock the next module; optional bonuses cannot block it. Modules 1–4 remain order-free. After their checks, Module 5 introduces bounded market/limit reasoning before stop/gap tasks; Modules 6–8 add risk, evidence and protection scenarios. Module 9 integrates already-taught tools across all four regimes rather than dropping the learner into unrestricted trading.

When an exit fails, disclose the dimensions and critical errors after the complete submission; link directly to the relevant named level, teach with immediate practice feedback, then permit retry on a reviewed alternate form. Keep first, latest and eventual pass distinct. If no fresh form exists, label the attempt familiar practice; do not claim an unseen result. No cooldown or single-attempt lock should make a learner unable to remediate.

Delayed review is separate from the current progression gate. In the target, retain a visible review-due/remediation state without erasing earlier passes; determine and review an additional retained-critical-risk gate before admission to advanced products or unrestricted modes. The exact fresh-form admission rule and lapse policy remain open, not secretly enforced through XP or streaks. Current guided simulation requires the first four module checks; endless simulation requires the first nine. Those gates do not implement the proposed retained-mastery requirement. Multiplayer eligibility also requires the first nine checks, but multiplayer execution remains unimplemented. Core completion does not require Module 10, and passing Module 10 alone does not authorize product-specific execution without the relevant simulator and safety contract.

## Confidence and evaluation

Optional confidence can support probability-accuracy analysis. For an answer submitted at probability `p = confidence / 100`, define `y = 1` when correct and `0` otherwise; mean `(p − y)²` is the binary Brier score, ranging from 0 to 1, with lower better. For example, confidence 0.8 gives 0.04 when correct and 0.64 when wrong. This score reflects more than calibration alone; reliability, resolution and outcome uncertainty contribute. See [Siegert's methods paper, equations 1–3](https://arxiv.org/html/1303.6182v2).

Legacy whole-set grading reports a descriptive mean Brier score and confidence sample count for that attempt only. Canonical interactive runs retain optional confidence in saved responses but do not report a Brier summary. Neither path aggregates a long-term calibration estimate. Evaluation should use comparable first-attempt questions and disclose sample counts, missing confidence and difficulty differences. Do not mix retry answers whose solutions have already been shown with unseen responses. Confidence about a quiz answer is not a market forecast. Small samples cannot support a stable calibration claim, and confidence never substitutes for correct critical-risk reasoning.

**Evaluation design proposal:** report baseline-to-first-exit change by construct separately from eventual passes, supported retries, delayed retention and unfamiliar application. Track misconception corrections and plan adherence alongside completion/engagement, not simulated return. Retain sample sizes, missingness, elapsed time and form difficulty; do not attribute improvement causally to the app without an appropriate study design. Assess whether learners can identify an unsuitable opportunity and choose not to trade. Human-reviewed rubrics, financial approval and evaluation of threshold validity remain necessary before stronger competence claims.

## Migration priority, gaps and verification

The v1 seed (`backend/config/database/init/02-initial_state.sql:4799–5013`) and quiz service (`backend/services/game_service/service/quiz_service.py:119–189`) are read-only evidence for pre/post concepts, zero thresholds and one-attempt behavior, not grading authority. The [learning audit](v1-audit/learning-simulation.md) records duplicated questions, profit/activity rewards and mission proxies; the [curriculum contract](curriculum/README.md) maps all v1 level IDs and named tutorial/quiz concepts into the ten-module order. Retain useful tasks but replace unsafe success criteria. Finish the full migration dispositions/contracts before additional UI polish; use the approved session handoff with the frontend designer for interaction/accessibility work, not as financial approval.

Before extending the implemented tasks or making a learning-effectiveness claim, resolve:

1. **Question banks:** independently review the 30 existing entry items against the blueprint; author reviewed parallel exit forms and delayed unseen variants with dimension coverage, justified critical flags, balanced distractors and exposure tracking. Protected stepwise diagnostics already exist; the 60/50 familiar practice/exit questions do not supply validated parallel or unseen banks.
2. **Mission contracts:** extend the existing choice/classification and observed-state verifiers to richer required/bonus tasks, with valid no-trade paths and frontend non-drag/keyboard equivalents. Routine interactive tasks already avoid mandatory essays. Preserve the written plan before every actual order; plan text quality needs separate reviewed assessment.
3. **Scenario binding:** extend beyond the single `m05-l01` audit to other lessons and tool-specific unlocks, with approved provenance, seed/version, friction, hidden future and held-out variants. The generic backend exists; stop-limit, realistic settlement and advanced-product assumptions require explicit implementation decisions rather than claims of parity.
4. **Rubrics and gates:** distinguish machine-verifiable constraints from human-reviewed plan/reflection quality; define retained-risk admission/lapse rules for advanced/endless/multiplayer; evaluate the proposed 80%-plus-critical threshold rather than labeling it validated mastery.
5. **Review and evidence:** independently approve financial wording, arithmetic, keys and scope against the content edition, then complete safety/accessibility and learning evaluation. Neither a session handoff nor passing tests replaces those reviews.
