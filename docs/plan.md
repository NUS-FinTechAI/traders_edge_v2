## Required review evidence

- Correctness: exact source/contract, successful path, rejected path, retry and reload. Existing tests that miss the requested behavior are not sufficient.
- Safety: game net-profit standings/rewards follow ADR 0003; learning mastery and badges retain their learning basis. No individual order-count/volume rewards; every simulated order has a prior written plan, abstention remains valid and copy avoids urgency or loss-chasing.
- Design: approved direction and meaningful map; actual 390px before/after evidence; 360/430/768px checks; 44px targets, focus, contrast, non-color state and reduced motion.
- Learning: entry diagnosis is distinct from exit assessment; documented remediation; optional bonus rules; reflection presence is not assessed reflection quality; repeated questions are not an unseen transfer test.
- Delivery: narrow scope, updated documentation, passing relevant local checks and hosted CI before merge. Do not label a gated phase complete while approval or evidence is missing.

The design selection gate precedes final tokens, component specifications and replacement product UI. Static concept prototypes are permitted for comparison. The owner selects the direction; product UI implementation requires a separate go-ahead after technical and safety review. Routine backend decisions can proceed within the existing publication authorization, with independent critique and evidence. Independent financial-content approval, permission restrictions, destructive operations and claims about measured learner outcomes cannot be self-approved.
