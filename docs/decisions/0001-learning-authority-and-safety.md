# 0001: Learning authority and safety

Status: accepted for discovery and design. Reviewed backend slices have been merged; replacement product UI still requires owner direction selection, a separate implementation go-ahead, and technical, safety and accessibility review.

## Context

The supplied research brief requires readiness, risk and investing foundations before execution and optional speculative trading. The screen mockup and v1 put strategies and technical tools earlier. The mockup also uses a “Sniper” badge, “Keep trading” copy and a reward countdown. These conflict with the brief’s focus on decision quality and its avoid list.

## Options

Copy the old sequence and visuals; retain the screen mechanics while applying the brief; or remove gamification entirely.

## Decision

Use the research brief as the product authority. Retain the screen inventory, treasure-map level navigation, normal and bonus stars, learning streaks, archive, profile rewards and process-based ranks. Design their visual appearance independently.

Use the ten-module sequence in the brief. Place analytical reasoning in Making Decisions. Optional advanced teaching requires all nine core module checks; technical and leveraged execution still need separately reviewed contracts and prerequisites. Do not move a v1 lesson into production merely because it exists.

Drop the “Sniper” badge and “Keep trading” tagline. Use learning language such as “Continue learning.” Remove reward countdowns rather than replacing them with a different urgency cue. The current learning streak records UTC days with rewarded learning events. Logins, check-ins, zero-XP bonuses and trading do not extend it; its display must not imply an obligation to return or place an order.

Leaderboards may compare learning XP or multiplayer process-based rank points. Do not feed profit, excess return, final account value, trade count or volume into ranking or reward formulas. Require written plans before simulated orders, and gate multiplayer and endless practice on mastery.

## Learning-loop clarification, 5 October 2026

The owner rejected the form-heavy connected client and specified sequential interactive learning, with the complete screen-reference workflow and Duolingo/Brilliant-style short tasks as the benchmark. This does not authorize copying either product's branding or claiming equivalent learning outcomes. Routine backend implementation decisions are delegated within the authorized scope; independent critique and evidence remain required. Visual direction selection remains the owner’s decision, with a separate go-ahead required for product UI implementation.

Retain the v1 module entry-check → levels/missions → exit-check structure, not its zero-threshold exit scoring or one-attempt lockout. Entry checks record a baseline before teaching; incorrect or uncertain answers must not prevent learning. Exit checks use separately authored applications and reviewed correctness/risk criteria. Keep the first response distinct from retries after explanations. Delayed repeated practice is not an unseen retention or transfer measure.

Use interactive choices, classification, comparisons and guided observations for ordinary learning steps. A required written plan belongs before every simulated order; it is not a requirement to add prediction/decision/reflection essays to every quiz. A note saved or minimum text length cannot earn a badge claiming reflective competence. Required and bonus missions need observable evidence and separate awards; optional work must not block required progression.

Preserve the existing v2 persistence, owner checks, exact command replay, private futures, learning XP and chart/data projections. At this reassessment, missing authored tasks, diagnostics and reward inventory justified extending those systems. The backend now implements those additions and one bound lesson audit; broader scenario and frontend integration remain pending. Module 1 uses non-trading readiness decisions; execution remains behind readiness prerequisites.

## Consequences

The old screen structure remains recognizable while old scoring and unlock rules must be rewritten. A learner choosing not to trade can still demonstrate the stated learning objective. Final visual selection and numerical assessment criteria still require review; delegated workflow approval is not independent content approval. A milestone passes only when its complete learner journey and failure/reload paths work, not because lesson counts, screenshots or unit tests increased.
