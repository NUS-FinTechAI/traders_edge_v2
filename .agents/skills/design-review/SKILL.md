# Design Review

All repository paths below are relative to the repository root.

Read `docs/design/anti-slop-checklist.md`, the selected reference in `docs/design/explorations/review.md`, and the current design specification if present. Inspect the running changed screen and its states; a component screenshot alone is insufficient for a navigation change.

Follow the beginner’s next action. Check that labels explain the task, unfamiliar terms are defined, the map encodes actual prerequisites and optional branches, and locked/error states offer an honest next step. Challenge decorative routes and repeated containers that obscure the hierarchy.

Inspect 390px first, then 360/430px and a tablet. Check 44px controls, keyboard focus/order, form labels, text enlargement, reduced motion and non-color feedback. Measure relevant contrast pairs. A passing scan is not a full assistive-technology audit.

Compare before/after evidence and verify links, selection, submission, retry and return paths. Review the fox as guidance rather than pressure or financial celebration. Report concrete issues with evidence and severity; do not claim participant comprehension from an expert walkthrough.
